
## 产品方案

### 信息架构

```
App
├── 宠物切换器（顶部宠物头像横滑 / 点击展开列表）
│   ├── 当前宠物信息条（物种图标 + 名字 + 体重，点击进设置）
│   ├── 宠物列表面板（底部 Sheet）：展示全部宠物，点击切换，支持新增
│   └── 新增宠物：复用引导页表单，独立完成新宠物的首次引导
│
├── 宠物信息（首次引导 / 设置入口）
│   ├── 物种切换（猫 / 狗，Segment）
│   ├── 名字、体重(kg)、目标体重(kg)、BCS 体况评分、年龄段、是否绝育、活动量（系数随物种从 `nutrition.ts` 读取）
│   ├── 每只宠物独立存 IndexedDB，`cat` 表允许多行，通过 `activePetId` 区分当前活跃宠物
│   └── 设置页（已完成首次引导的宠物）：「保存」下方提供「删除当前宠物及关联数据」；须二次确认；清空该宠物的 `cat` / `foods` / `weightLogs` / `feedingLogs` 数据后自动切换到剩余宠物；若无剩余宠物则回到首次引导（`onboardingDone = false`），以便重新开始
│
├── Tab 1：热量计算
│   ├── 食物类型切换（干粮 / 湿粮）
│   ├── 热量输入方式切换（bordered button group，默认 kcal/kg）
│   │   ├── 直填 kcal/kg
│   │   └── 成分反算（蛋白% 脂肪% 灰分% 纤维% 水分%）
│   ├── 计算结果：每日可喂 g 数
│   └── 可保存为「常用猫粮」（关联当前宠物）
│
└── Tab 2：减肥计划
    ├── 开始减肥计划：必须已保存当前喂食模式所需热量密度配方，且当前宠物 BCS > 5；条件不满足时按钮禁用并提示补齐喂食配方与 BCS
    ├── 顶部 Card：第 N 周目标 + 总进度条 + 固定每周目标区间
    ├── 每日喂食克数（干粮 / 湿粮 分别显示）
    ├── 体重记录（时间线 + 圆润曲线折线图）
    └── 打印计划：生成 A4 纵向专用计划表，供用户打印后贴在冰箱上执行

辅助入口
├── 设置抽屉（三条横线图标）：语言切换（中文 / English / 日本語）与体重单位切换（kg / lb）
└── 关于：隐私说明、算法来源、完整计算说明、非兽医诊疗声明
```

### 多宠物管理

- 支持在一个 App 实例中管理多只宠物（猫 / 狗），每只宠物拥有独立的档案、食物配置、体重记录和喂食日志。
- **宠物列表**：所有宠物以列表形式展示（圆形物种头像 + 名字 + 体重），点击切换当前活跃宠物；切换后所有 Tab 内容实时更新。
- **新增宠物**：从宠物列表面板点击「＋ 新增宠物」进入新宠物的首次引导流程，完成后自动切换到新宠物。
- **删除宠物**：设置页提供「删除当前宠物」按钮，仅删除当前宠物及其关联的 `foods` / `weightLogs` / `feedingLogs` 数据；若列表中仅剩一只宠物，删除后回到首次引导状态（`onboardingDone = false`）并创建默认宠物档案。
- **数据隔离**：`foods`、`weightLogs`、`feedingLogs` 三张表均通过 `petId` 外键关联到 `cat` 表；所有查询按 `activePetId` 过滤，确保宠物间数据完全隔离。

### 多语言

- App 必须支持中文、英文、日文三种界面语言，默认跟随浏览器语言；若浏览器语言不在支持范围内，默认中文。
- 用户可在顶部三条横线图标打开设置抽屉，并在设置内切换语言；选择写入 `localStorage`，键名为 `react-cat:locale`。
- 所有用户可见文案、按钮、错误提示、aria-label、关于页内容、A4 打印计划内容都必须走统一 i18n 字典。
- 数据库中的用户输入内容（宠物名、食物名、记录日期、克数、体重）不翻译；单位使用当前语言的显示规则，但数值仍统一按 kg、g、kcal 计算。

### 单位偏好

- 体重单位支持 `kg` / `lb` 两档，入口位于设置抽屉，使用 Segment button，不使用 `<select>`。
- 选择写入 `localStorage`，键名为 `react-cat:weightUnit`。
- IndexedDB 与所有计算仍统一保存和使用 kg；界面展示、体重滚轮与 aria-label 按当前单位换算。

## UX 设计

### 导航

底部悬浮胶囊 Tabs，两个按钮：`热量计算` / `减肥计划`，固定在屏幕底部，背景模糊 blur。首次进入应用时：若已保存常用猫粮/狗粮且满足当前喂食模式的热量密度（干粮模式需干粮 `kcal/kg > 0`；湿粮模式需湿粮；混合模式需干湿均有），**默认选中「减肥计划」**；否则默认选中「热量计算」。用户可随时切换，当次会话内记住选择。

#### 宠物切换器

页面顶部为当前宠物信息条（`CatInfoBar`），左侧为圆形物种图标（猫/狗），中间显示名字与体重，右侧为设置齿轮图标。点击信息条展开**宠物列表面板**（底部 Sheet，复用 `Sheet` 组件）：

```
┌─────────────────────────────┐
│  我的宠物                    │
│                             │
│  🐱 小橘 · 4.2kg       ✓   │  ← 当前选中宠物高亮
│  🐶 旺财 · 12.5kg          │  ← 点击切换
│                             │
│  [＋ 新增宠物]               │  ← 进入新宠物引导流程
└─────────────────────────────┘
```

- 宠物列表按创建时间排序，当前选中宠物右侧显示勾选图标。
- 点击某只宠物立即切换（关闭面板 + 刷新 Tab 内容），无需确认。
- 「新增宠物」按钮跳转至 `PetOnboarding` 页面，新宠物默认 `onboardingDone = false`，走完整引导流程。
- 面板底部使用安全区适配（`pb-[env(safe-area-inset-bottom)]`）。

### 输入交互原则（移动端优先）

所有数值/选项输入均按**移动端原生触感**设计，**禁止**直接套用桌面浏览器交互方式：

- 数字（kcal/kg、成分百分比、体重）→ 大号步进器（＋/－ 长按连增）或滚轮选择器，配合 `inputMode="decimal"` 唤起数字键盘，**不使用** `<input type=number>` 的浏览器原生加减箭头与滚轮调值。
- 切换类（食物类型、热量输入方式）→ Segment / bordered button group，点击切换，非下拉 `<select>`。
- 触控目标 ≥ 44×44pt，反馈即时（按压态 + 轻震动 haptics）。
- **全局禁用浏览器默认聚焦样式**：在 `src/index.css` 的 `@layer base` 对 `*`、`:focus`、`:focus-visible` 统一设置 `outline: none` 与 `-webkit-tap-highlight-color: transparent`，避免点击图表（Recharts SVG）、非表单区域等出现系统蓝框或 iOS 灰色高亮，保持类原生 App 观感。
- 需要聚焦反馈的控件（如文本输入、可拖拽进度条）**不得**依赖浏览器 `outline`，改用 Tailwind 的 `focus:ring-*` / `focus-visible:ring-*`（`box-shadow`）或边框色变化；键盘导航场景优先 `focus-visible`，避免触控点击时出现多余环。
- **图表（Recharts）**：折线图等纯展示/点选 tooltip 的图表设置 `accessibilityLayer={false}`，避免图表容器获得焦点；曲线类型仍为 `type="natural"` / `monotone`。

表单控件选择规则：

- `体重` / `kcal/kg` / `成分百分比` → 使用项目内自定义 `<Stepper>`，中间输入框为 `type="text"` + `inputMode="decimal"`，左右按钮支持长按连增；适合需要精确微调的连续数值。
- `BCS 体况评分` → 使用官方截图素材嵌入的紧凑视觉引导 + 1–9 分 Segment；猫使用 `SCR-Cat.png`，狗使用 `SCR-Dog.png`。截图放入静态资源目录并在产品内直接展示；图片区域默认紧凑显示，不占据首屏主体空间。
- `成分反算` 表单 → 默认展开为一组成分 `<Stepper>`：蛋白、脂肪、灰分、纤维、水分；输入过程中实时计算 NFE / kcal/kg。
- `年龄段` / `是否绝育` / `活动量` / `食物类型` / `热量输入方式` → 使用 Segment 或 bordered button group；选项少、决策明确，禁止使用 `<select>`。
- `体重记录` → 任意日期均可记录、**不限制每周一条**（「建议每周称一次」仅作文案提示）；底部面板默认今天，用自定义 `<Calendar>` 选日期（禁选未来日期），体重用 `<DecimalWheelPicker>`（双列滚轮，整数 + 小数），**不使用** `<Stepper>`。同一日期仅保留一条记录（再次保存即覆盖），历史记录可点击编辑或删除。
- `名字` → 使用普通文本输入，但高度、间距与按压区域仍需满足移动端触控目标。
- `日期` → 默认今天；体重记录面板直接展示 `<Calendar>` 选日期。

`<Stepper>` / `<WheelPicker>` 参考同目录 `docs/demo-stepper.html` 实现，组件化时需保留以下行为：

- Stepper 布局为「减号按钮 / 数值输入 / 加号按钮」，按钮触控尺寸不小于 56px，按下态需有缩放或底色变化。
- Stepper 中间输入框使用大字号、居中、等宽数字；宽度随内容长度自适应，单位紧跟数值显示。
- Stepper 输入框必须使用 `type="text"`，按字段设置 `inputMode="decimal"` 或 `inputMode="numeric"`；禁止使用 `<input type="number">`。
- Stepper 输入过程中只保留数字和小数点；失焦时按 `min / max / decimals` 夹取并格式化。
- Stepper 单击 `+ / -` 立即变化；长按 400ms 后开始连续变化，并逐步加速；每次有效变化触发轻震动。
- WheelPicker 基于 `scroll-snap` 实现吸附居中，显示 5 行，首尾留白保证边界值可滚到中央。
- WheelPicker 当前项需高亮并轻微放大；滚动停止后触发轻震动。
- 所有震动调用均需先判断 `navigator.vibrate` 是否存在，保证非支持环境正常运行。

### BCS 目标合理性

BCS 体况评分用于降低目标体重误填风险，不作为兽医诊断。字段写入 `cat` 表：`bcsScore`（1–9，nullable）、`bcsAssessedAt`（ISO string，nullable）。首次引导、宠物设置与开始减肥计划前都应展示 BCS 输入；开始减肥计划要求当前宠物已记录 BCS 且分值大于 5。

展示规则：

- 猫 / 狗按物种展示对应截图，截图区域高度固定，允许横向滚动或等比缩放，避免撑高表单。
- 评分控件展示 1–9 分；当前选中分值下方只显示一行解释和一行动作建议。
- BCS 4–5 为理想范围；BCS 6 为轻度超重；BCS 7–9 为高风险减重范围；BCS 1–3 为偏瘦或营养风险范围。
- BCS 7–9、幼龄、妊娠/哺乳、已有疾病、明显厌食、疑似肌肉流失、目标热量低于安全下限时，不显示强鼓励文案，只显示“建议先与兽医确认目标与热量”的短提示。
- 提示文案放在发生判断的组件内部，例如 BCS 控件下、计划卡片底部或打印计划注意事项，不使用全局通知、浏览器通知、Toast 或常驻横幅。

### 坚持性短提示

本项目不实现浏览器通知、推送通知、产品内通知中心或定时提醒。原本提醒体系改为上下文短提示：

- 喂食记录卡：当天未记录时显示一行“今天还没记录实际喂食”；已记录但偏离计划时显示“较计划 ±N kcal”。
- 体重记录卡：超过 10 天未称重时显示“距离上次称重已超过 10 天”；没有足够数据时不判断趋势。
- 减肥计划卡：若连续两次体重记录下降过快、停滞或目标风险较高，只显示一行复盘建议，不弹窗。
- 所有提示都必须短、贴近相关数据、可被用户忽略，不增加额外操作负担。

### A4 打印计划

用户在减肥计划 Tab 点击「打印计划」生成 A4 纵向专用计划表，并通过浏览器打印能力打印或保存为 PDF。打印内容不是现有界面的截图、HTML 转图片或页面导出，而是独立排版的纸面执行表；内容为固定计划，不随 Web App 后续记录自动变化。当用户修改宠物资料、BCS、目标体重、食物热量密度、喂食模式或计划开始日后，需要重新生成。

A4 内容必须包含：宠物名、物种、当前体重、目标体重、BCS、计划开始日、每日目标 kcal、每日干粮 / 湿粮克数、干湿热量比例（如适用）、建议称重频率、连续 14 天每日完成打勾区、每周体重填写区、过快下降提示、算法来源摘要与非兽医诊疗声明。打印版文案随当前语言切换，中文、英文、日文都必须可读且不溢出 A4；没有配置干粮或湿粮时，对应栏显示未配置而不是 0。

打印预览页可以信息密度较高，但主 App 界面必须保持紧凑和中等信息密度；日常界面只提供入口，不把打印版全部内容塞入计划卡片。

### 关于

顶部提供「关于」入口，打开独立 Sheet 或全屏轻量页面，内容包括：

- 隐私说明：数据默认存储在本机 IndexedDB；未实现云同步、后端通知或远程上传；BCS 截图作为本地静态资源展示。
- 算法来源：PNA、AAHA、AAFCO、APOP、WSAVA / Purina BCS 资料。
- 完整计算说明：RER、MER、成分反算、干湿混合、减重热量区间、体重参考周逻辑、BCS 风险分流。
- 限制说明：本项目不替代兽医诊疗，BCS 与热量估算可能受用户判断、食物标签、称重误差和个体差异影响。

关于页允许内容较长，但必须通过分段折叠或紧凑小标题组织；默认只露出隐私、来源、计算、限制四个区块，避免首屏冗杂。

## 数据模型

### IndexedDB 表结构（Dexie.js v2）

所有表通过 Dexie.js 管理，数据库名 `react-cat`。

```
cat 表（宠物档案）
├── id (auto-increment PK)
├── species, name, weightKg, idealWeightKg
├── bcsScore, bcsAssessedAt
├── lifeStage, neutered, activity
├── feedingMode, mixedDryRatio
├── dietStartDate, dietStartWeightKg
├── onboardingDone, updatedAt

foods 表（常用食物密度）
├── id (auto-increment PK)
├── petId (FK → cat.id, 索引)
├── name, foodType, kcalPerKg
├── macros (JSON, nullable)
├── createdAt

weightLogs 表（体重记录）
├── id (auto-increment PK)
├── petId (FK → cat.id, 索引)
├── date, weightKg

feedingLogs 表（每日喂食记录）
├── id (auto-increment PK)
├── petId (FK → cat.id, 索引)
├── date (与 petId 联合唯一)
├── dryGrams, wetGrams
```

- `petId` 外键关联 `cat.id`，确保宠物间数据完全隔离。
- `feedingLogs` 的日期唯一约束由 `&date` 改为 `[petId+date]` 联合唯一索引（同一宠物同一天仅一条记录）。
- 所有查询、写入操作均以当前 `activePetId` 过滤或关联。

## 计算逻辑（配置化）

### 科学依据与产品口径

本项目只提供家庭喂食估算与体重追踪，不替代兽医诊疗。对 BCS ≥ 7/9、已有疾病、幼龄/妊娠/哺乳、明显厌食或需要喂到 RER 以下的宠物，界面应提示在兽医指导下执行减重计划。

| 来源 | 本项目采用方式 |
|------|----------------|
| [Pet Nutrition Alliance: Calculating Calories Based on Pet Needs](https://petnutritionalliance.org/wp-content/uploads/2023/03/MER.RER_.PNA_.pdf) | 使用 `RER = 70 × BWkg^0.75`；MER 用 `RER × 系数`，系数按物种、生命阶段、绝育/完整状态和活动量估算；PNA 明确 MER 只是起点，需按 BCS、当前摄入和复评调整。 |
| [Pet Nutrition Alliance Calorie Calculator](https://petnutritionalliance.org/resources/calorie-calculator/) | 减重按理想/目标体重和 BCS 评估；本项目每周目标统一采用 0.5–1% 固定区间；零食不超过每日总热量 10%。 |
| [AAHA 2021 Nutrition and Weight Management Guidelines](https://www.aaha.org/wp-content/uploads/2021/06/new-2021-aaha-nutrition-and-weight-management-guidelines-with-ref.pdf) | 营养评估应结合 BW、BCS、MCS、饮食史、活动与环境；超重/肥胖时基于理想体重计算并持续复评；显著限热时应考虑兽医处方减重粮，避免营养不足。 |
| [AAFCO Calorie Content](https://www.aafco.org/resources/startups/calorie-content/) | 成分反算使用宠物食品修正 Atwater：`NFE = 100 - 蛋白 - 脂肪 - 纤维 - 水分 - 灰分`，`ME kcal/kg = [(3.5×蛋白) + (8.5×脂肪) + (3.5×NFE)] × 10`，按标签原样百分比计算。 |
| [APOP Veterinary RER/MER Calculator](https://www.petobesityprevention.org/veterinary-der-calculator-1) | 作为 RER/MER 公式一致性的交叉参考；同样把 RER 作为基础，再乘活动/生命阶段系数得到 MER。 |

实现优先级：食品热量密度以包装标注 kcal/kg 为准；没有标注时才使用 AAFCO 成分反算。日常喂食用当前体重 MER 估算。减肥计划在开始时记录起始体重；第 1 周按起始体重生成目标体重区间，第 2 周起按上一计划周体重记录平均值生成目标体重区间；若上一计划周没有体重记录，则回退为计划起始体重。目标体重区间使用固定 0.5–1%/周速率递减，并以目标体重兜底；目标热量按 `MER - ((参考体重 - 本周目标体重) × 7700 / 7)` 计算区间。每次体重记录用于复评趋势，不自动替代兽医诊断。

所有系数放 `src/config/nutrition.ts`：

```ts
// RER 静息能量 (kcal/day) = 70 × 体重kg^0.75
// 来源：PNA / APOP；猫狗通用，用作热量估算底座。

// 维持能量 MER = RER × lifeFactor × activity
// 来源：PNA / AAHA；用于「热量计算 Tab」日常喂养量，属于起始估算，需按 BCS、实际摄入和体重趋势复评。
// 生命因子（按物种，× RER）：PNA 常用 MER 系数；幼龄统一取保守 2.0×RER，实际幼龄需求可随月龄变化。
lifeFactor: {
  cat: { kitten: 2.0, adult_neutered: 1.2, adult_intact: 1.4, senior: 1.1 },
  dog: { kitten: 2.0, adult_neutered: 1.6, adult_intact: 1.8, senior: 1.4 },
}

// 活动系数（× RER）：狗活动差异远大于猫，high 段上调以覆盖运动犬/工作犬
activity: { low: 1.0, moderate: 1.2, high: 1.4 }

// Atwater 修正系数 (kcal/g)：AAFCO 宠物食品标准值，与物种无关；
// NFE = 100 - 蛋白 - 脂肪 - 灰分 - 纤维 - 水分；
// kcal/kg = [(3.5×蛋白) + (8.5×脂肪) + (3.5×NFE)] × 10，按标签原样百分比计算。
atwater: { protein: 3.5, fat: 8.5, nfe: 3.5 }

// 固定减重速率（每周体重百分比）：0.5–1%。
// 体重目标 = 参考体重按 0.5–1%/周下降后的区间；
// 热量目标 = MER - ((参考体重 - 本周目标体重) × weightLossEnergyKcalPerKg / 7)；
// 第 1 周从减肥起始体重计算；第 2 周起从上一计划周体重记录平均值计算。
// 本周目标体重按 safeWeightLossRate 下降，并以用户填写的目标体重兜底。
safeWeightLossRate: {
  cat: { min: 0.005, max: 0.01 },
  dog: { min: 0.005, max: 0.01 },
}

// 体重变化热量折算粗估值，用于从周减重 kg 推算每日热量缺口。
weightLossEnergyKcalPerKg: 7700
```

> **减肥口径说明**：开始计划时记录起始体重。第 1 周以起始体重为参考，第 2 周起以上一计划周体重记录平均值为参考；未填写目标体重时回退为当前体重。目标热量按「MER 扣除 0.5–1%/周对应的每日热量缺口」计算。喂食克数建议与记录对比默认使用热量区间上限，避免自动给出更激进的限热量。
